# 单调栈 vs 单调队列

> 这是一份示例 output，演示 LLM 怎么基于 wiki/ 生成长答 / 对比报告。
> 完成后可以回流到 wiki/maps/ 作为新的对比图。

## TL;DR

- **单调栈**：一端 push、一端 pop；专治"**下一个更大 / 更小元素**"
- **单调队列**：两端都可弹（deque）；专治"**滑窗最值**"
- 两者都 O(N) 摊还；都靠"**新元素让旧的废了，赶紧 pop**"

## 本质区别表

| 维度 | [[../../wiki/techniques/monotonic-stack]] | [[../../wiki/techniques/monotonic-queue]] |
|---|---|---|
| 底层结构 | `stack` / `vector` | **`deque`**（要两端弹） |
| 解决问题 | 下一个更大 / 更小元素 | 滑窗最大 / 最小值 |
| 弹出位置 | 只在栈顶 | **队尾（失效）+ 队首（过期）** |
| 何时弹队尾 | "新元素让栈顶'见了答案'" | "新元素让队尾的旧元素永不可能是 max" |
| 何时弹队首 | 不需要 | "队首下标超出窗口左边界" |
| 摊还复杂度 | O(N) | O(N) |
| 经典代表题 | LC 84 / 42 / 739 | LC 239 / 862 / 1438 |

## 共同点

两者都遵循同一个**单调性维护原则**：

```text
当新元素 x 到来时：
  如果 x 让某些"已存的旧元素"永远不可能再成为答案
  → 立即把它们弹出
```

差别在于"旧元素永远不可能成为答案"的**判定条件**和"答案是什么"。

## 直觉图解

### 单调栈：每个元素只在乎"右侧第一个比我大 / 小的"

```text
nums = [2, 1, 5, 3]
栈 (递减): [2]  → [2,1]  → 遇 5 把 1, 2 都结算 → [5]  → [5, 3]
                        ↑ 5 是 1 和 2 的"右侧第一个更大"
```

### 单调队列：维护"窗口内目前的候选最大值"

```text
nums = [1, 3, -1, -3, 5, 3, 6, 7],  k = 3
i=0: dq=[1]
i=1: dq=[3]            (3 > 1, 弹掉 1)
i=2: dq=[3, -1]
i=3: dq=[3, -1, -3]    窗口满，输出 dq.front=3
i=4: dq=[5]            (5 比 3 还大，全弹)，输出 5
...
```

## 配题三道（每个 5 行思路）

### 1. 接雨水（LC 42） — 单调栈

每个低柱子被"夹在两根高柱子之间"才能存水。
**单调递减栈**逐层结算：当前柱 i 比栈顶高时，pop 栈顶 mid，左邻 left 一起算 `(min(h[left],h[i]) - h[mid]) * (i - left - 1)`。

详见 [[../../wiki/problems/trapping-rain-water]]。

### 2. 滑窗最大值（LC 239） — 单调队列

`deque` 存下标、对应值递减；新元素入队前**弹掉所有 ≤ 它的队尾**；窗口左端越界就弹队首；队首始终是当前窗口最大值。

详见 [[../../wiki/techniques/monotonic-queue]]。

### 3. 跳跃游戏 VI（LC 1696） — 单调队列优化 DP

朴素：`dp[i] = max(dp[i-k..i-1]) + nums[i]`，O(NK)。
用单调队列维护 dp 在窗口 `[i-k, i-1]` 上的最大值 → O(N)。

这是 **DP + 单调队列**的经典组合，远比 [[../../wiki/data-structures/heap|堆]] 快。

## 选型口诀

```text
"下一个 X" → 单调栈
"窗口内 X" → 单调队列
"DP 转移涉及窗口最值" → 单调队列优化
"动态查询任意位置最值" → 堆 / 平衡 BST，不是单调结构
```
