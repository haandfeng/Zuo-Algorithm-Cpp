# 复杂度

> **TL;DR**：复杂度衡量"算法运行时间 / 占用空间随输入规模 N 怎么变"。我们关心**渐近行为**和**最坏情况**。常用记号：大 O（上界）、Ω（下界）、Θ（紧界）。

## 大 O 直觉

$T(N) = O(f(N))$ 表示存在常数 $c, N_0$，使得对所有 $N \geq N_0$ 有 $T(N) \leq c \cdot f(N)$。

口语化理解：**N 足够大时，T 不会超过 f 的某个常数倍**。

## 常见复杂度阶层

从快到慢：

| 阶 | 名称 | 典型场景 |
|---|---|---|
| O(1) | 常数 | 哈希表查找均摊、数组访问 |
| O(log N) | 对数 | [[binary-search]]、[[heap]] 操作 |
| O(√N) | 根号 | 试除法判素数、莫队 |
| O(N) | 线性 | 一遍扫描、[[two-pointers]] |
| O(N log N) | 线性对数 | 归并 / 快排 / 堆排（[[sorting]]） |
| O(N√N) | — | 莫队总复杂度 |
| O(N²) | 平方 | 双重循环、暴力 DP |
| O(N²·log N) | — | 部分图算法 |
| O(N³) | 立方 | [[shortest-path|Floyd]]、矩阵乘 |
| O(2^N) | 指数 | 状压 [[backtracking]]、暴搜 |
| O(N!) | 阶乘 | 全排列 |

## 输入规模与可承受复杂度

经验对照（C++ 1 秒大约 1e8~1e9 次基本操作）：

| N 范围 | 上限复杂度 |
|---|---|
| N ≤ 10 | O(N!) |
| N ≤ 20 | O(2^N · N) |
| N ≤ 100 | O(N³) |
| N ≤ 1000 | O(N²) 或 O(N² log N) |
| N ≤ 1e5 | O(N log N) |
| N ≤ 1e6 | O(N) 或 O(N log N) |
| N ≤ 1e8 | O(N) |
| N ≤ 1e9 | O(log N) 或 O(√N) |

面试时也常用这个表反推：题目给 N=1e5，那基本要找 O(N log N) 或 O(N) 解法。

## Master 定理

适用于**分治**形式的递推：

$$
T(N) = a \cdot T(N/b) + f(N)
$$

设 $\log_b a = c$：

| 比较 | 解 |
|---|---|
| $f(N) = O(N^{c-\epsilon})$ | $T(N) = \Theta(N^c)$ |
| $f(N) = \Theta(N^c)$ | $T(N) = \Theta(N^c \log N)$ |
| $f(N) = \Omega(N^{c+\epsilon})$ | $T(N) = \Theta(f(N))$ |

经典实例：

- 二分：$T(N) = T(N/2) + O(1)$ → $\Theta(\log N)$
- 归并：$T(N) = 2T(N/2) + O(N)$ → $\Theta(N \log N)$
- Strassen 矩阵乘：$T(N) = 7T(N/2) + O(N^2)$ → $\Theta(N^{\log_2 7}) \approx N^{2.81}$

## 均摊复杂度（Amortized）

**单步可能慢，但 N 步合起来摊得开**。

经典例子：

- **动态数组扩容**：单次最坏 O(N)，但 N 次 push 总共 O(N) → 均摊 O(1)
- **并查集**（路径压缩 + 按秩合并）：单次最坏 O(log N)，均摊 O(α(N)) ≈ O(1)
- **单调栈 / 队列**：每个元素入栈出栈各一次 → 总 O(N)

写题时如果说"N 个操作总 O(N)"就能过，不用管单步是不是 O(1)。

## 空间复杂度

容易被忽略：

- **递归**有**栈空间**！纯递归 DFS 树深度 N 时空间是 O(N)，不是 O(1)
- **哈希表 / 备忘录**显式开 O(N) 数组
- **滚动数组**可以把 [[dp]] 二维 O(NM) 优化为 O(min(N,M))

## 常见误区

- ❌「O(2N) 写成 O(N) 是错的」
  → 大 O 忽略常数，O(2N) = O(N)。但**面试讨论性能**时常数有意义，需要说"O(N)，常数 2"。
- ❌「快排平均 O(N log N)、最坏 O(N²)，所以是 O(N²)」
  → 大多数题目接受**平均 / 期望复杂度**；快排的最坏可以通过随机化避免。但**安全检查**或**算法竞赛**仍可能要求 O(N log N) 严格上界，那就用归并 / 堆排。
- ❌「递归一定比迭代慢」
  → 递归的常数大（栈帧、压栈），但渐近复杂度相同；现代编译器还可能做尾递归优化。
- ❌「N=1e5，O(N²) = 1e10，绝对 TLE」
  → 通常是，但常数极小的 O(N²)（纯加法、不取模）在 5 秒限时下偶尔能过。**估算要先看常数和限时**。

## 怎么算复杂度

实战技巧：

1. **看循环嵌套**：两层 for + 内层独立到 N → O(N²)
2. **看分治递推**：写 $T(N) = ...$，套 Master
3. **看数据结构操作**：哈希 O(1)、平衡树 O(log N)、堆 O(log N) push/pop
4. **看摊还**：双指针 / 单调栈 / 单调队列 / 并查集都靠摊还
5. **看输入分支**：if 进入慢路径的概率 → 期望复杂度
