# 模拟与构造

> **TL;DR**：模拟题 = "**严格按题目说的做**"，没有捷径，靠**清晰的数据结构选择 + 仔细的边界处理**。构造题 = "**给出一个满足条件的方案**"，常需要**找规律 + 数学直觉**。

## 模拟题套路

### 1. 读清题、画清状态

模拟题失败 90% 来自**没读懂题**。
建议：先用纸笔画 1~2 个例子，列状态变量。

### 2. 选对数据结构

| 题型 | 推荐 |
|---|---|
| 网格 / 棋盘 | 二维 vector |
| 链表删除 / 插入 | [[../data-structures/linked-list\|双链表]] |
| 优先调度 | [[../data-structures/heap\|优先队列]] |
| LRU / LFU | hash + 链表 |
| 字符串解析 | [[../data-structures/stack\|栈]] |
| 区间合并 | 排序 + 扫描 |

### 3. 抽出函数

把"一步操作"抽成函数（`move()`、`tick()`、`apply(op)`），主循环只调度。

## 构造题套路

### 1. 找规律

打表 / 手算几个小例子 → 找输出与输入的关系。

### 2. 倒推

从目标状态倒推过程。

### 3. 极端情况

- 全相同
- 已排序 / 已逆序
- 长度 1 / 2

### 4. 对称 / 周期

利用对称性减少状态数。

## 何时是模拟 / 构造

| 信号 | 类型 |
|---|---|
| "按以下规则…" | 模拟 |
| "设计一个数据结构…" | 模拟 + 数据结构 |
| "返回任意一种满足…" | 构造 |
| "请给出一个…的最小 / 最大例子" | 构造 |

## 易错点

- 没读清题就开始写
- 边界 corner case 漏掉（空、单元素、长度为 0）
- 数据结构选错——比如本应链表用了 vector 导致 O(N²)
- 模拟过程中**某步骤被反复调用**——抽函数避免重复
